# 模型广场动态分组分类开发方案

## 1. 文档目的

本文设计模型广场如何接入分组类型（以下简称“分类”），使用户能够按照后台当前配置的分类、分组、模型和价格逐层浏览，并在详情页准确比较可用分组。

本文包含开发设计及第 14 节的实施、审查和验收记录。实现与部署分开登记，不能把本地检查通过等同于线上已发布。

相关事实与能力边界见 [模型广场与媒体能力重构交接说明](model-marketplace-refactor-handoff.md) 和 [模型广场端点与图片能力维护记录](model-catalog-endpoint-capabilities.md)。本轮交付范围是分组分类、分组范围内的目录/价格/接口展示，以及管理端影响预览。

## 2. 设计结论

模型广场的分类必须是数据驱动的，前端不得固定 `OpenAI`、`Claude`、`Gemini`、`Grok`、`国模`、`图片`、`视频`、`其他` 这些名称，也不得通过模型名、厂商名或 endpoint 猜测分类。

分类的唯一业务来源是后台已配置的分组类型和分组到类型的映射：

```text
GroupTypes(type_id -> name/icon/order)
GroupTypeMap(group_name -> type_id)
GroupRatio(group_name -> ratio)
UserUsableGroups(user_scope -> visible group names/descriptions)
Model.EnableGroup(model -> enabled group names)
```

分类名称、图标、顺序和分组归属都可以随后台配置变化。分类 ID 必须保持稳定，名称可以修改；前端保存和 URL 传递分类 ID，不能使用分类名称作为主键。

模型可以同时属于多个分类。例如，一个模型同时绑定 OpenAI 分组和图片分组时，在 OpenAI 分类和图片分类中都可被找到，但在全部分类视图中只渲染一张模型卡片。

分类是浏览维度，不等于模型厂商、API endpoint、计费类型或模型能力。厂商、endpoint、标签和计费方式继续作为独立筛选条件。

模型广场继续使用现有 `/api/pricing` 的价格读模型。本方案不接入外部模型定价插件，不在模型广场推导官方价格，也不从模型名称猜测缺失的价格、能力或请求参数。

## 3. 当前事实与问题边界

### 3.1 当前线上事实快照

2026-10-25 以当前公开服务只读核对得到：

- `/api/pricing` 返回 69 个模型、34 个可用分组，并返回 `data`、`group_ratio`、`usable_group`、`vendors`、`supported_endpoint`、`auto_groups` 等字段。
- 当前 `/api/pricing` 没有返回 `group_types` 或分组类型归属。
- `/api/user/groups` 已返回分组类型数组，以及每个可用分组的 `type` 元数据。
- 当前后台已配置的类型包括 OpenAI、Claude、Gemini、Grok、国模、图片、视频、其他，但这些只是当前数据，不能写入前端常量或设计成固定枚举。
- 同一个模型可能跨多个类型。例如 `gpt-image-2` 同时可从 OpenAI、图片和其他分组找到；分类数量不能直接相加得出模型总数。
- `auto` 是自动路由入口，不属于普通可配置分类，不应出现在普通分类标签或普通分组比较中。

线上快照仅用于验证当前链路，不是接口契约。分类配置、模型数量和分组数量发生变化后，页面仍必须正常工作。

### 3.2 当前代码链路

```text
后台分组类型配置
  -> ratio_setting.GroupTypes / GroupTypeMap
  -> service.GetUserGroupOptions()
  -> GET /api/user/groups

模型、渠道、能力、价格
  -> model.GetPricing()
  -> controller.GetPricing()
  -> GET /api/pricing
  -> web/src/features/pricing
```

当前模型广场只消费 `/api/pricing`，所以它能拿到分组名称和倍率，却拿不到分组类型。若前端自行再请求 `/api/user/groups`，会产生两个风险：

1. 两个请求可能处于不同的用户上下文、缓存时间或配置快照。
2. 前端需要重复拼接分组、类型、模型之间的关系，容易把不可见分组或失效映射带到页面。

因此，正式方案应由 `/api/pricing` 返回和模型价格同一快照生成的公开分组目录；`/api/user/groups` 继续服务令牌选组等用户组功能，不作为模型广场分类的第二事实源。

### 3.3 必须保持的边界

| 边界 | 设计要求 |
| --- | --- |
| 模型公开名与上游模型名 | 广场继续展示公开模型名，不用渠道映射后的上游名称替换。 |
| 分类与厂商 | 分类可按业务调整，不能自动等同于 `vendor_name`。 |
| 分类与 endpoint | “图片”“视频”等类型可以与 endpoint 同时存在，但不能由 endpoint 自动创建分类。 |
| 分类与计费 | 分类只改变浏览范围和价格比较范围，不改变计费表达式。 |
| 分类与插件 | 插件提供路由和用量事实；分类配置仍由分组类型维护。 |
| 可见性 | 只返回当前用户能看到的分组和模型，不把管理员或其他用户的分组暴露给广场。 |
| 缺失映射 | 不猜测归属。分组没有有效类型时只能标记为“未分类”显示状态。 |

## 4. 目标用户体验

### 4.1 页面层级

页面按以下顺序组织：

```text
搜索
  -> 动态分类导航
      -> 动态分组选择
          -> 厂商 / 标签 / endpoint / 计费方式筛选
              -> 模型卡片或模型表格
                  -> 模型详情
                      -> 当前分组价格与限制
                      -> 同分类分组比较
                      -> 接口和使用说明
```

分类导航位于广场主内容顶部，使用服务端返回的 `order` 排序。导航至少包含一个由前端固定的“全部”入口；除此之外不固定任何分类名称。

桌面端可以使用横向分类标签或紧凑的分类按钮，移动端使用横向滚动的标签栏。分类数量增加时，不能依靠硬编码的 `grid-cols-*` 或固定按钮列表；应该允许横向滚动、折叠或“更多”菜单。

### 4.2 分类导航规则

分类项由接口动态产生；当前实施已选定“有可见分组就显示，即使模型数为零”的规则：

- 只显示当前用户可见分组中至少有一个分组的类型。
- 如果某类型有可见分组但没有模型，仍显示，并显示 `0 个模型`；没有任何可见分组的类型不公开。
- 分类数量、模型数量按去重后的公开模型计算，不按分组数量相加。
- 图标优先使用类型配置中的 `icon`；未知图标复用项目图标加载器的占位显示，不因未知图标导致分类消失。
- 类型 ID 相同而名称变化时，当前选中状态保持；名称直接更新。
- 类型顺序变化时，下次读取目录按新的 `order` 排序；相同顺序使用名称和 ID 做稳定排序。
- 类型被删除或不再对当前用户可见时，旧 URL 不得自动映射到另一个类型，页面清除该类型筛选并显示当前有效目录。

### 4.3 分组选择规则

分组选择器只显示当前分类下的可见分组；选择器选项包含：

```text
分组名称
倍率（当前用户实际倍率）
分组说明（可选，截断显示）
```

分组选择器提供“全部分组”。当用户从分类 A 切换到分类 B 时，如果当前分组不属于 B，则清除具体分组筛选；不能继续显示一个与面包屑不一致的隐式分组条件。

当用户直接选择某个分组时，页面自动将分类定位到该分组的 `type_id`，并在面包屑中显示“分类 / 分组”。如果该分组没有类型，则定位到系统生成的“未分类”显示状态，而不是创建持久化类型。

### 4.4 搜索和筛选组合

搜索默认在当前分类、当前分组和其他筛选条件的结果集内执行。搜索词应覆盖模型公开名、描述、厂商名、分组名和标签，不能因为分类筛选而丢失对分组说明的搜索能力。

筛选条件应保持为独立维度：

- 分类：`category=<type_id>`。
- 分组：`group=<group_name>`。
- 厂商：`vendor=<vendor_name>`，沿用既有参数。
- endpoint：`endpointType=<endpoint_type>`，沿用既有参数。
- 计费类型：`quotaType=<token|request|task>`。
- 标签：`tag=<tag>`。

URL 中保存分类 ID 和分组名，支持刷新、复制链接、浏览器后退和模型详情返回。分类名称修改后，旧 URL 仍能根据稳定 ID定位新名称。

系统“未分类”使用独立的 `unclassified=true` 查询参数；真实分类仍使用 `category=<原始类型 ID>`。界面内部的真实分类值采用 `type:<ID>`，与系统控件值分离，因此管理员把类型 ID 命名为 `all` 或 `unclassified` 时也不会冲突。不存在新增保留类型 ID 的迁移。

### 4.5 无分类配置和未分类分组

当后台没有任何有效类型配置时：

- 不显示一组写死的品牌分类。
- 页面保留“全部”入口和现有分组筛选。
- 若存在未分类可见分组，显示一个由数据状态生成的“未分类”状态入口；该入口不是可编辑类型，不写入 `GroupTypes`。
- 页面提示管理员配置分类，但不根据模型名、厂商或 endpoint 猜测分类。

当只有部分分组没有类型时：

- 已配置类型正常显示。
- 未分类分组归入“未分类”状态入口。
- 未分类模型仍可被“全部”找到，不能因为分类缺失而从广场消失。

`auto` 只显示为自动路由说明，不进入“未分类”数量，也不作为普通分组选项参与价格比较。

## 5. 公开数据契约设计

### 5.1 `/api/pricing` 增量字段

保留现有字段，新增和规范化以下字段。新增字段采用增量方式，旧客户端可以继续读取现有 `usable_group` 和 `enable_groups`。

```json
{
  "group_catalog_version": "stable-hash",
  "group_types": [
    {
      "id": "stable-type-id",
      "name": "后台配置的名称",
      "icon": "optional-icon-key",
      "order": 10,
      "group_count": 3,
      "model_count": 12
    }
  ],
  "groups": [
    {
      "name": "public-group-name",
      "type_id": "stable-type-id",
      "type_name": "后台配置的名称",
      "type_icon": "optional-icon-key",
      "type_order": 10,
      "ratio": 0.4,
      "description": "当前用户可见的分组说明",
      "model_count": 8
    }
  ],
  "data": [
    {
      "model_name": "public-model-name",
      "enable_groups": ["public-group-name"],
      "group_type_ids": ["stable-type-id"],
      "group_endpoint_types": {"public-group-name": ["openai-response"]},
      "group_plugin_keys": {"public-group-name": []}
    }
  ]
}
```

字段语义：

| 字段 | 规则 |
| --- | --- |
| `group_catalog_version` | 对当前用户可见的类型、分组、映射、模型归属和价格范围生成稳定版本标识；配置变化后必须变化。 |
| `group_types[].id` | 稳定业务 ID，不随名称修改变化；禁止前端生成。 |
| `group_types[].name` | 当前展示名称，允许管理员修改，必须经过后台校验。 |
| `group_types[].order` | 展示顺序，服务端先排序，前端仍需做稳定排序保护。 |
| `group_count` | 当前用户可见、有效且属于该类型的分组数量。 |
| `model_count` | 该类型下去重后的公开模型数量。 |
| `groups[].type_id` | 有效类型 ID；未分类时为 `null`。不使用 `__auto__`。 |
| `groups[].ratio` | 当前请求用户实际适用倍率；前端只展示和计算，不重新推导特殊用户组倍率。 |
| `groups[].model_count` | 当前用户可见且启用该分组的去重模型数量。 |
| `data[].group_type_ids` | 服务端依据该模型当前可见分组计算的类型 ID 集合，用于分类过滤和数量统计。 |
| `data[].group_endpoint_types` | 由已启用 ability、实际渠道配置和插件绑定解析的分组端点；隐藏分组从响应中删除。 |
| `data[].group_image_capabilities` | 可选的分组图片能力，组内多个渠道使用既有保守交集；单组选中时读取该组参数。 |
| `data[].group_plugin_keys` | 每个可见分组实际绑定的公开插件键。用于限制供应商价格，不包含渠道 ID、密钥、上游地址或内部绑定配置。 |

### 5.2 为什么不能只返回 `group_types`

只返回类型列表仍然不够，因为模型广场还需要知道：

- 当前用户是否能看到该类型下的分组。
- 某个分组的倍率和说明是什么。
- 某个模型属于哪些分类。
- 模型卡片在当前分类下应该使用哪些分组计算价格。

因此必须返回已经按用户范围过滤、按同一快照生成的 `groups` 与 `data[].group_type_ids`。前端不应再次把全局 `GroupTypeMap` 和用户可见分组拼接。

### 5.3 与现有字段的兼容策略

- `usable_group` 在第一阶段继续保留，供旧页面和旧客户端使用。
- `group_ratio` 保留旧消费者所需的已配置数值型 `auto` 条目；新 `groups` 目录、分类计数和固定价格比较始终排除 `auto`。
- 新模型广场优先使用 `groups`；若服务端仍是旧版本、响应缺少 `group_types/groups`，前端只保留旧分组筛选，不显示动态分类栏，不猜测分类。
- `enable_groups` 继续保留，作为公开模型可见分组名称的兼容字段。
- `group_type_ids` 缺失时，前端不能依据 `vendor_id`、模型前缀、endpoint 或标签生成类型；只能把该模型归入当前已知的未分类状态或使用旧分组筛选。
- `/api/user/groups` 继续返回令牌选组所需的类型数据，但模型广场不再依赖第二次请求来计算分类。

### 5.4 快照一致性

`group_types`、`groups`、`data[].group_type_ids`、`group_ratio` 和 `usable_group` 使用同一次请求内读取的用户分组配置生成。类型定义与映射使用既有原子快照，基础倍率与用户覆盖分别先读取副本。模型、端点、图片能力和插件绑定来自同一份既有定价能力快照。不能在前端拼接两个不同接口的用户范围；本方案不把原有多个独立 option 的保存升级为全局事务。

后台成对更新类型定义和映射已经具备原子保存语义；接入模型广场时还应让以下变化触发同一组目录版本更新：

- 类型定义新增、删除、改名、改图标、改顺序。
- 分组类型映射变化。
- 分组可见性、分组说明或分组倍率变化。
- 分组与模型的 enabled ability 变化。
- 影响模型可用分组的渠道、映射或模型状态变化。

实施采用以下策略：分类目录在每次 `/api/pricing` 请求中投影，类型修改不额外缓存目录，因此本节点保存成功后的新请求直接读取新配置；渠道/模型变化沿用既有能力缓存失效机制。其他节点沿用 `SyncOptions(SYNC_FREQUENCY)` 的数据库同步，默认 60 秒。前端查询按用户 ID 和用户组隔离，前台每 60 秒重新验证，管理端保存相关设置后立即使 `pricing` 查询失效。因此跨节点、跨浏览器是有界的最终一致性，默认窗口约为配置同步周期加一个前端轮询周期；本次没有引入新的广播服务或无限期目录缓存。

## 6. 价格和详情页语义

### 6.1 价格计算范围

价格显示必须依赖用户当前的筛选范围：

| 当前选择 | 模型卡片主价格 |
| --- | --- |
| 全部分类 + 全部分组 | 当前用户可见分组中的最低有效价格，并标记“起价”或可见分组范围。 |
| 某一分类 + 全部分组 | 只在该分类包含的可见分组中取最低有效价格。 |
| 某一具体分组 | 只显示该分组价格，不再取其他分组最低价。 |
| 请求计费/任务计费模型 | 使用现有计费读模型和用量条件；如果不同分组有不同有效价格，按当前筛选范围显示。 |
| 未配置价格或无法比较 | 显示“价格未配置”或当前已有的明确状态，不用零值或猜测值填充。 |

当前实现中的 `getDisplayGroupRatio` 只接受具体分组或全部分组。接入动态分类后，必须增加“当前分类允许的分组集合”这一输入；否则用户进入 Claude 分类时，卡片可能错误地使用图片或其他分类中的最低倍率。

同理，价格排序必须在当前分类/分组过滤后的集合上进行。分类切换不能只改变卡片数量，而不改变价格和排序依据。

供应商价格与分组倍率必须先配对。示例：供应商甲单价为 9，只服务倍率 0.1 的分组；供应商乙单价为 1，只服务倍率 3 的分组。合法起价为 `min(9 × 0.1, 1 × 3) = 0.9`，不能计算 `min(9, 1) × min(0.1, 3) = 0.1`。前端为每个可见供应商附加仅用于显示的 `display_group_ratio`，动态汇总及排序识别已经应用的倍率，不二次相乘。该字段不写入任何计费配置。

卡片中的供应商价格区间表示各供应商的起价；完整的逐组价格在详情比较中展示。任务价格排序继续采用已声明用量示例的总价，并保留示例标签；没有对应单位价格或可计算示例的模型排在末尾。

### 6.2 模型卡片

模型卡片建议显示：

1. 模型名称、厂商、模型描述。
2. 分类徽标：显示该模型在当前可见分组中所属的动态类型，最多显示两个，更多使用数量提示；分类名称直接来自接口。
3. 当前分类内的可用分组摘要，例如“3 个分组可用”。具体分组名称可显示前一个并以 `+N` 收起，完整内容通过 tooltip 或详情页查看。
4. 当前筛选范围内的价格，明确单位 `/1M`、`/1K`、每次请求、每秒或其他既有计费单位。
5. endpoint、功能标签和已有能力摘要。
6. 如果当前筛选的是具体分组，显示“按此分组计价”；如果是全部范围，显示“起价”。

卡片不应把分类名称复制到模型的持久化元数据中，也不应因为分类改变而修改模型记录。

### 6.3 详情抽屉和详情页

从卡片进入详情时保留 `category`、`group`、`vendor` 等搜索参数。详情页的首屏应显示：

```text
模型名称
当前浏览范围：分类 / 分组
当前范围内的价格
可用 endpoint
当前用户可见的分组说明
```

未选分类或具体分组时，保留既有“Base Price／参考基础价”区块，并展示全部可用分组的实际价格；选定分类或具体分组后，首屏价格应用该范围。这样不会移除已有基础价参考，也不会把基础价冒充选定分组的价格。

“分组定价”区域分三种状态：

- 选定具体分组：该分组置顶并标记“当前选择”，其他同分类分组作为可比较项。
- 只选分类：先显示该分类下的分组，再提供“其他分类中的可用分组”折叠区。
- 未选分类：显示全部可见分组，按类型顺序分组展示；未分类分组单独显示。

每个分组行至少包含名称、分类徽标、倍率/实际价格、说明、是否自动路由、可用 endpoint 范围和切换按钮。`auto` 只显示自动切换链及其说明，不作为可直接比较的固定分组价格。

分类、分组和 endpoint 的组合必须保持一致。如果详情页因为全局模型聚合显示了某个 endpoint，而当前分组没有该 endpoint，应明确标注“其他可用分组支持”，不能让用户误以为当前分组一定支持。

当前实现只在选中范围显示实际解析到的端点，其他分类的分组可展开比较；切换范围后重建 API 参数与示例视图。模型元数据中的自定义端点声明继续保留在全局目录中，不自动填入未经该组能力解析证明的端点。多组图片参数保留既有保守聚合，单组参数使用该组能力。

分组说明会显示在选择器及详情常驻说明区。若管理员在说明中填写了特殊接入地址，页面原样展示；不从自由文本提取或猜测 Base URL，不新增未被配置的地址覆盖。

### 6.4 体验入口

详情页可以提供“查看接入说明”“前往 Playground”“创建 API Key”等入口，但入口必须带上当前模型和分组上下文。进入创建 Key 时，仍使用真实的用户组选组和权限校验；模型广场的筛选结果不能绕过后端授权。

图片和视频模型继续复用现有能力链路：插件协议决定路由，图片能力配置决定参数展示，计费 schema 决定价格展示。分类只帮助用户找到这些模型，不把分类当作图片/视频请求参数 schema。

## 7. 管理端协作设计

### 7.1 分组类型管理

现有分组类型管理器继续作为分类配置入口，但需要明确以下行为：

- 类型 ID 只在创建时生成，改名、改图标、改顺序不改变 ID。
- 类型名称为空、重复、过长或包含不允许的控制字符时拒绝保存。
- 类型删除前显示受影响分组和模型数量；确认后清除映射，公共广场下次刷新不再显示该分类。
- 类型排序直接影响模型广场分类顺序和详情页分组排序。
- 未知图标仍允许保存，沿用项目图标加载器的占位预览，不新增分类图标枚举。
- 类型定义和类型映射继续成对原子保存，避免广场出现名称与归属不一致。

### 7.2 管理端预览

管理端分组定价表建议增加“广场影响”摘要：

```text
分类：Claude
可见分组：8
关联模型：12
未分类可选分组：0
```

修改类型归属后，管理员可以在保存前看到分类模型数量变化；该预览只读当前编辑草稿，不直接改变 `/api/pricing`，保存成功后才发布新目录版本。

### 7.3 分类配置与模型元数据分离

模型管理中不添加一份独立的 `category` 字段。否则会出现模型元数据分类和分组类型分类互相冲突。模型的分类结果由当前可见分组实时计算，模型元数据只维护名称、描述、图标、标签、endpoint 和真实能力等自身属性。

## 9. 缓存、刷新和异常处理

### 9.1 配置变化

分类配置保存成功后的预期顺序：

```text
管理员提交类型定义 + 类型映射
  -> 后端事务提交
  -> 发布新的运行态类型快照
  -> 使分组目录/定价聚合缓存失效
  -> 生成新的 group_catalog_version
  -> 下一次 /api/pricing 返回新目录
  -> 前端检测版本并清除失效筛选
```

如果类型保存失败，前端保留编辑草稿并显示失败原因；不能在失败后把旧配置或空配置误显示成已发布结果。

### 9.2 旧 URL 和失效筛选

页面加载时对 URL 做一次纯数据归一化：

- `category` 不在当前类型目录：删除 `category`，保留其他合法筛选。
- `group` 不在当前可见分组：删除 `group`，保留合法 `category`。
- `group` 存在但不属于 `category`：删除 `group`，不偷偷切换分类。
- 类型名称变化：保留 `category` ID，显示新名称。
- 类型被删除后分组未重新归类：分组进入未分类状态，不丢失模型。

页面应向用户显示一条轻量提示，例如“部分筛选条件已更新”，但不能把内部 ID、配置错误堆栈或未授权分组名称泄露给普通用户。

### 9.3 服务端数据异常

- `group_types` 是非法结构：后端保留最后有效运行态，不发布部分目录；前端显示现有可用目录或明确错误状态。
- `group_type_map` 指向不存在的类型：该分组作为未分类，不能阻断其他合法分组。
- 类型图标未知：使用通用图标。
- 分组倍率缺失：沿用现有价格读模型的明确缺失语义，不以 `1` 猜测展示价格。
- 模型没有任何可见分组：不进入普通用户模型列表；管理员诊断页面可以单独显示配置问题。

## 10. 测试和验收矩阵

### 10.1 后端契约测试

1. 返回类型按 `order/name/id` 稳定排序。
2. 新增类型后 `/api/pricing` 自动出现，不修改前端常量。
3. 改名只改变显示名称，ID、分组归属和 URL保持有效。
4. 改序只改变排序，不改变模型归属。

7. `auto` 不出现在普通类型数组、类型计数和普通分组比较中。
8. 普通用户、特殊用户组、管理员和匿名范围只收到各自可见分组。
9. 同一模型跨多个类型时，`group_type_ids` 去重且模型只出现一次。
10. 类型定义和映射的数据库更新仍然是原子操作；保存失败不能产生半套目录。

### 10.2 前端组件测试

1. 使用任意自定义类型名称渲染分类导航，测试中不得依赖 OpenAI 等固定名称。

3. 分类切换清除不兼容分组；选择具体分组自动定位其类型。
4. 旧响应缺少新字段时只显示旧分组筛选，不产生猜测分类。

10. 移动端分类和分组选择使用与桌面端相同的状态源。
11. 未知图标、长分类名称、长分组说明和大量分类不会破坏布局。

## 13. 最终验收标准

只有同时满足以下条件，才能认为动态分类设计落地：

- 分类功能不内置当前分类名称枚举、名称分支或分类到图标的固定映射；共享图标库继续按配置中的图标键工作。
- 后台新增、改名、改序、删除分类后，模型广场无需重新发布前端即可正确反映。
- 分类使用稳定 ID，名称变化不破坏 URL、筛选状态和详情返回。
- 模型跨多个分类时全部分类只显示一张卡片。
- 分类和具体分组筛选改变价格计算范围，不能引用其他分类的最低价格。
- 未分类和自动路由有明确的显示边界，不因缺失配置丢模型或制造幽灵分类。
- 公开响应只包含当前用户可见的分组、分类、模型和价格范围。
- 模型广场仍保持模型元数据、真实 endpoint、图片能力、视频能力和计费读模型的职责边界。
- 旧客户端和旧接口字段继续可用，新增字段缺失时前端安全降级到旧分组筛选，不猜测分类。
- 相关测试、类型检查、lint、生产构建和线上只读核对全部通过。

### 14.2 阶段发现与处理

| 阶段 | 审查发现 | 处理与保护 |
| --- | --- | --- |
| 0 | 公开广场仍是平铺分组；分类只在另一接口中提供。线上快照仍为 69 个模型、34 个选项。 | 确认主分支基线及接口样本；同一公开响应提供新目录，保留旧字段。 |
| 1 | 不能依赖传入数组已排序；未分类不能排在正常类型前；类型/模型计数需要去重。 | 显式稳定排序，未分类组排后，按公开模型名去重；版本忽略旧接口人为附加到首行的静态标记。 |
| 1 | 模型级全局端点和供应商可能来自隐藏分组。 | 保留实际分组能力，在输出时裁剪；不原地修改共享能力缓存。 |
| 2 | 本地筛选 state 和 URL 相互同步可能覆盖加载中的深链接。 | 路由成为唯一状态源；目录未就绪不清理有效 URL，目录就绪后只归一化失效项。 |
| 2 | 真实类型 ID 可能与系统“全部”“未分类”同名。 | 使用独立 URL 参数及带前缀的内部控件值；不新增业务保留 ID。 |
| 3 | 按全局最低倍率排序/展示会引用其他分类；供应商最低价与最低倍率也可能不属于同一路由组合。 | 限制候选组和实际绑定，逐供应商应用可用组倍率；汇总已应用倍率的金额时不再次相乘。 |
| 3 | 直接替换参考基础价破坏两项既有媒体展示回归。 | 无显式范围时保留参考基础价；有范围时应用分组价格，保留所有逐组比较。 |
| 3 | API 选择状态可能在同模型切组后沿用旧端点。 | 按模型、选组、分类范围和端点集合重建 API 参数/示例视图。 |
| 4 | 只刷新管理设置会使已打开的广场继续缓存旧分类。 | 保存成功使 `pricing` 前缀查询失效；其他浏览器前台定期重新读取。 |
| 4 | 草稿计数会把共享模型重复累加。 | 按模型名计算类型影响，明确统计范围是当前用户可见目录。 |
| 4 | 固定类型列中仍有固定宽度选择器，单元格内边距可能裁切右侧控件。 | 选择器改为随单元格内容宽度显示，保留原固定列宽。 |
| 5 | 64 字符分类名在手机详情标题中撑出容器。 | 浏览器先复现，再让分类/分组文字缩小到可用宽度并换行；390px 视口复核通过。 |
| 5 | 清空查询参数后，搜索防抖结果尚未更新时立即断言列表，造成测试竞态。 | 回归等待真实可见列表状态，仍保留 URL 与结果的精确断言，不使用固定 sleep。 |
| 5 | 新目录排除自动路由时仍需维护旧 API 的数值型 `auto` 倍率。 | 旧 `group_ratio` 保留已配置值，新目录持续排除 `auto`；补充 API 兼容断言。 |
